# 财报自动更新

`Watch All Company Earnings` 全年全天按小时触发（每小时第 4 分钟），检查处于财报窗口的公司。它一次读取 Earnings-Image-Studio 已发布的数据，按股票代码匹配公司，并用相同的官方附件解析器独立检查本平台自己的公司列表，覆盖仅在本平台跟踪的公司。

同步只更新新季度或新披露的当前季度，保留历史数值。美元以外的报表必须完成汇率转换才能写入；累计数据不能当成单季度。无法解析的公告会转向其他财务来源，仅刷新当前及新季度，再核对最新财报是否确实写入。现金流按更新公司增量补齐，未披露值不估算。

AMD 的 SEC 8-K 被检测到但附件未解析时，会直接读取 AMD Newsroom 的 HTML 合并报表；核对公告日期、报告期、百万美元单位和三个月列后，提取 GAAP 利润、净资产及单季现金流，不等待数据商或 CompanyFacts 更新。解析失败仍保留备用来源，并由最终检查报告财报滞后。

每天的完整财务、价格、市值和历史现金流刷新继续保留。两条更新任务共用并发锁，避免同时写入数据。有效数据提交后显式发布 Pages，并读取公开数据核对。数据脚本的版本由内容哈希更新，避免页面继续使用旧缓存。

失败不阻断其他公司的有效更新，但最终任务会标为失败并保留逐公司诊断。每日任务中，财务脚本先回滚未通过金额校验的公司；财务、市值、现金流和股价步骤分别记录结果，继续发布已验证的变化，最后汇总失败。股价的新鲜度检查仍保留，失败时不写入不完整行情。GitHub 通知是否发送邮件取决于账户的 Actions 通知设置。`Earnings Scheduler Watchdog` 每小时第 19 分钟及发布/刷新完成后检查是否漏掉了定时任务；超过 90 分钟未启动且没有活动任务时补触发。

小时级巡检不是发布时延保证。GitHub 调度、发行人数据开放时间和源站可用性仍会影响完成时间；新报表版式可能需要维护。没有取得可验证的新值时保持旧的有效数据并报告问题。

2026-11-04 排障：11 月 3 日 21:39 UTC 的巡检已发现 AMD 新 8-K，但附件没有解析出季度值，备用来源仍止于 2026Q2，最终检查报 `AMD: release detected but financial data still lags`。当天每日刷新还因 SharonAI 的金额校验失败退出，导致其他公司的有效变化没有走到提交步骤。以上两条路径已修复；AMD 2026Q3 官方数值与现金流来源同时保存，后续刷新会重新应用。
